# S1 원가 연동 — management 쪽 설계 (2026-10-20, 대표님 확인 대기)

구매 시스템(plenty-storage)의 메뉴 원가를 읽어 와 부서별 P&L 을 만든다.
원칙: **원가는 구매 시스템이 주인 · 매출·식수는 management 가 주인 · P&L 은 management 가 계산.** management 는 원가를 다시 계산하지 않는다.
참고(읽기 전용): 구매 repo `docs/S1-원가API-연동안내.md`, `ROADMAP.md` §7.

## 1. menu_code — 행사 메뉴 ↔ 코드표

행사 메뉴(`event_food_items`)는 지금 `menu_name`(예: "A set") 자유 문자열이다. 여기에 `menu_code` 를 더한다.
**같은 "A set" 이 기업/웨딩 두 메뉴**라 행사 구분(`event_type`)으로 갈라야 한다.

운영 데이터(살아 있는 행사의 메뉴 라인 398건) 기준 매핑 미리보기:

| 행사 메뉴명 | 구분 | 라인 | → 코드표 메뉴 | 비고 |
|---|---|---|---|---|
| A set | WEDDING | 149 | 웨딩 A세트 | 2025 이전 71건 포함 |
| A set | MICE | 46 | 기업 A세트 | |
| B set | WEDDING | 45 | 웨딩 B세트(콤비) | 2025 이전 24 |
| B set | MICE | 3 | 기업 B세트(콤비) | |
| C set | WEDDING | 13 | 웨딩 C세트 | 2025 이전 8 |
| C set | MICE | 3 | 기업 C세트 | |
| D set | MICE | 1 | 기업 D세트 | |
| Korean Lunch Box | MICE | 65 | 한식도시락 | |
| Chinese Lunch Box | MICE | 4 | 중식도시락 | |
| Dessert Plate(L) | MICE | 8 | 디저트 L(45인분) | 기준인분 45 |

→ **매핑 가능 349 / 코드 없음 18(Coffee Break) / 의도적 미매핑 31(식사없음)**. 실제 코드 값은 `/menus` 로 이름 대조해 붙인다(키 등록 후 미리보기).
적용(운영 쓰기)은 미리보기 확인 후 대표님 승인으로. 새로 만드는 행사는 메뉴 선택 시 코드가 같이 저장되게.

## 2. 식수 — 이론원가의 곱하는 수

- 원천: **행사리뷰 `실제 식사 인원`(actual_meal_count)** — 이미 연회팀이 쓰는 칸, 새 입력 칸을 만들지 않는다. (리뷰에 식수 있는 행사 121건)
- 세트·도시락 메뉴: 이론원가 = 실제 식사 인원 × `1인분원가`
- 수량 메뉴(디저트·떡·커피브레이크 수량): 이론원가 = 수량 × `합계원가`(기준인분 단위) — 수량 = 접시/판 수로 본다 (**확인 ③**)
- 한 행사에 세트가 두 개 이상(예: A세트 + 한식도시락)이면 리뷰 식수 하나로는 못 나눈다 → 그런 라인만 라인별 실제 인원 칸(`actual_count`)을 둔다.
- **식수가 비어 있으면 이론원가를 비워 둔다**(GTD 로 대신 채우지 않는다 — 잠정값 금지와 같은 원칙). 화면에 "식수 미입력 N건" 표시. (**확인 ④**)

## 3. 매출 부서 태그

매출 라인은 메뉴별이 아니라 **항목별**(컨벤션이용료·Food·Coffee Break…)이라, 부서 태그는 항목에 기본값을 두고 행사 라인에서 바꿀 수 있게 한다.

| 매출 항목 | 기본 부서 | COST% 분모 |
|---|---|---|
| Food · Snack Plate | 컨벤션_주방 (코드표 매출귀속부서) | 포함 |
| Bev. | 컨벤션_홀 | 포함 |
| Coffee Break | 컨벤션_홀 ❓ | 포함 — **확인 ⑤** |
| Corkage | 비식음 ❓ | 제외 — **확인 ⑤** (원가 없는 매출) |
| 컨벤션이용료 · Media Wall · Booth · Stage · System · Flower · 가톨릭대관료 | 비식음 | 제외 |

## 4. P&L 뷰 (새 화면, 관리자)

월 선택 → 부서 4열(컨벤션_주방 · 컨벤션_홀 · 카페_주방 · 카페_홀) + 합계.

| 행 | 계산 | 출처 |
|---|---|---|
| 식음 매출 | Σ 그 달 DEF 행사의 부서 태그 매출 (비식음 제외) | management |
| 이론원가 | Σ 식수 × 1인분원가 (수량 메뉴는 수량 × 합계원가) | management 식수 × storage 스냅샷 |
| 실제원가 | `/cogs` 실제원가 | storage |
| COST% | 실제원가 ÷ 식음 매출 | |
| 이론 COST% | 이론원가 ÷ 식음 매출 | |
| 로스 | 실제원가 − 이론원가 (금액·%) | |

상태 표시: 스냅샷 404 → "아직 마감 전" · `소급: true` → "2026-10 단가로 소급한 값" · `완전: false` → "원가 일부 미확인(N메뉴)" · cogs 2026-08 이전 → "실제원가 없음".
**카페 두 부서는 management 에 매출이 없다** → 실제원가만 보이고 COST% 는 "매출 없음" (**확인 ⑥**).

## 대표님 결정 (2026-10-21) → 구현 반영

1. Rice Cake Plate = **떡 플레이트**(CV-DES-01). Dessert Plate(M/L) = CV-DES-02/04.
2. Coffee Break = **구매팀에 코드 추가 요청**. 코드가 생기면 `server/src/lib/s1Pnl.ts` 표에 한 줄 적으면 된다(그 전엔 원가 빈칸, P&L 에 "코드 없음 N라인").
3. 떡·디저트 플레이트 = **접시 수** × 합계원가(기준인분). 커피브레이크 = 커피+쿠키 세트 **인원수** × 1인분원가.
4. **2026 이후** 종료된 DEF 행사에 식사 메뉴가 있는데 실제 식사 인원이 비면 알림(행사리뷰 화면 배너 + Slack 주 1회). **0 은 입력한 값**(식사 안 함)이라 알리지 않는다. 2025 이전은 그대로.
5. 매출 부서: Coffee Break = **커피 10,000 → 컨벤션_홀 / 쿠키 3,000 → 컨벤션_주방 (10:3 배분)**, Corkage = 컨벤션_홀. 행사별로 매출 탭에서 덮어쓸 수 있다.
6. management 는 **컨벤션만**. 카페 P&L 은 구매 시스템에서.
7. 메뉴별 원가 화면 → 구매 시스템 스냅샷 읽기 전용으로 교체(옛 자체 레시피 계산 화면 내림, 서버 API 는 남김).

### 구현 메모
- `menu_code` 는 메뉴명 × 행사 구분으로 **자동 판정**한다(코드표 불변이라 표 하나로 충분). 사람이 다르게 지정할 때만 라인에 저장 → **기존 행사 일괄 쓰기가 필요 없다.** 미리보기: `/api/storage/menu-code-preview`, `scripts/_preview-s1-mapping.ts`.
- 한 행사에 식사 세트가 2개 이상(15개 행사)이면 행사 식음 메뉴에 **메뉴별 실제 인원** 칸이 나타난다. 비면 P&L 에서 "세트 2개 이상" 으로 빠진 목록에 뜬다.
- 화면: 메뉴별 원가(읽기 전용) · 📒 컨벤션 P&L(관리자) · 매출 탭 항목별 부서 선택 · 행사리뷰 식수 미입력 배너.
